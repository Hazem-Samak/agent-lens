## Research and inspected seams

Primary sources inspected 2026-10-27:

- [npm view](https://docs.npmjs.com/cli/v11/commands/npm-view/): named metadata fields and JSON output; explicitly request `@latest`, not the configurable default tag.
- [npm dist-tag](https://docs.npmjs.com/cli/v11/commands/npm-dist-tag/): `latest` is a publisher-managed tag, not necessarily the largest published version; beta/next have no automatic stable-channel meaning.
- [npm config](https://docs.npmjs.com/cli/v11/using-npm/config/): online/offline cache policies and registry settings. A fresh empty npm transport cache is required for Refresh; npm10.9.8 maps prefer-online to no-cache revalidation; a previously cached response may still participate in protocol validation, so do not claim empty-cache provenance from that flag alone.
- [npmrc](https://docs.npmjs.com/cli/v11/configuring-npm/npmrc/): scope registry overrides and user/global configuration. Never dump configuration/authentication or parse `.npmrc` wholesale.

Current code: `NpmOwnershipProbe` verifies manager, prefix, global root, package manifest/bin and selected executable with bounded descriptor-anchored reads and final revalidation. `VerifiedInstallation` is invocation evidence, not a durable permission token.

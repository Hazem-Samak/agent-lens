## Strongest objection (independent, non-blocking)

**The six-hour reuse promise is now honest but economically thin, and its honesty depends on one untested ordering guarantee.** On a cache *hit*, R3 still mandates 8 npm process launches per scoped subject — the cache saves exactly one `view`. With both shipped npm tools, a Check can spend most of the 60s stage on validation of data already on disk, and a slow-but-healthy npm yields `budgetExhausted` beside a valid unexpired record. R3 licenses this explicitly and types it, and the Homebrew-first ordering means npm slowness cannot evict brew — but that ordering is the single clause standing between this design and DeepSeek-R2's coupling objection, and AC07's "mixed Homebrew/npm runs never overlap" tests serialization, not *order*. **Cheap freeze-strengthening (optional):** add to AC07 an injected-monotonic case proving that an npm subject exhausting the budget leaves the already-completed Homebrew batch results published (order falsifiable, not just asserted). Even without it, every degradation path is neutral, typed, publication-safe and cache-write-safe — which is why this is an objection to record, not a blocker.

FINDINGS AND DISPOSITIONS

1. Busy-gate release/claim ordering (pre-existing, non-blocking).
   NpmUpdateOperation and NpmUninstallOperation acquire the process gate before claiming the
   preparation. A simultaneous second execute that fails the gate can call releaseUnconsumed()
   before the gate winner claims, leaving the winner with a consumed preparation. The result is
   zero processes, never two; the frozen requirement forbids two mutation processes. The new
   combined scenario deliberately starts the second confirm after the first is already inside its
   launched wrapper process, so it tests the claimed case and records cleanupWarnings == []. No
   order change was made in this pass; noted for a future bounded Core cleanup.

2. observeFresh nil-base fallback (no finding).
   The fallback now uses Foundation temporaryDirectory instead of a captured TMPDIR. Both
   production callers pass their owned operation root; the new service-level regression covers the
   Check/Refresh path, which is the only path that previously inherited the captured value.

3. Combined interruption determinism (no finding).

   task. The 0.5 s install delay only keeps the first process alive while the competing confirm

   competingState cancelled, competingProcessStarted false, interruptedState interrupted,
   interruptedProcessStarted true, interruptedAfterInstallState installedAndOnPath, and two
   uninstall invocations (interrupted + final).

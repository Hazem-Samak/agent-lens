While slot exclusivity currently protects it, adding the guard provides symmetry and protects against stale completions.

2. **Multi-hop dangling symlink resolution in `observeEntryRemoval`**
   - **Location:** [`Sources/AgentLensCore/Operations/NpmUninstallOperation.swift:465-478`](file:///Users/corvette/Documents/Projects%20Coding/Agent%20Lens/Sources/AgentLensCore/Operations/NpmUninstallOperation.swift#L465-L478)
   - **Details:** If `selectedEntryPath` is an external symlink pointing to `{prefix}/bin/<tool>`, and `{prefix}/bin/<tool>` is itself a symlink to `{prefix}/lib/node_modules/<pkg>/...`: if npm deletes the package directory but leaves `{prefix}/bin/<tool>` as an unremoved dangling symlink, `lstat(target)` on `{prefix}/bin/<tool>` succeeds (returns 0). Line 478 evaluates to false, returning `.failed` (`observationFailed = true`), leading to `.uncertain`. This fails closed (prevents false success), but using `stat` on the target to test for `ENOENT` across symlink chains would directly observe whether the link destination is live or dangling.

3. **Spurious cleanup warning on busy gate with replayed preparation**
   - **Location:** [`Sources/AgentLensCore/Operations/NpmUninstallOperation.swift:190-198`](file:///Users/corvette/Documents/Projects%20Coding/Agent%20Lens/Sources/AgentLensCore/Operations/NpmUninstallOperation.swift#L190-L198)
   - **Details:** When `gate.acquire()` fails, `preparation.releaseUnconsumed()` is called. If the preparation was previously claimed (replayed), `releaseUnconsumed()` returns `false`. This `false` is passed to `cleanupOK: false` in `noProcessOutcome`, generating the warning `"The owned operation scratch root could not be removed safely."` even though the root is owned and in active use by the running operation.

4. **Buffer sizing for `readlink` in `observeEntryRemoval`**
   - **Location:** [`Sources/AgentLensCore/Operations/NpmUninstallOperation.swift:466-468`](file:///Users/corvette/Documents/Projects%20Coding/Agent%20Lens/Sources/AgentLensCore/Operations/NpmUninstallOperation.swift#L466-L468)
   - **Details:** `readlink` reads into a fixed `PATH_MAX` (1024-byte) buffer. If a symlink target reaches or exceeds `PATH_MAX`, `count < buffer.count` is false, falling through to `.failed` (`observationFailed = true`). This fails closed, but dynamically sizing or explicitly checking against `PATH_MAX` would prevent treating long paths as observation failures.

## VERIFIED STATIC INVARIANTS

The following were verified as sound by static code analysis:
1. **Tri-state removal observation:** `observePackageRemoval` and `observeEntryRemoval` distinguish absent (`ENOENT`/`ENOTDIR`), present-with-identity, replaced identity, released target, dangling residue, and observation failure. Exit 0 alone never results in `.succeeded`; `.succeeded` strictly requires exit 0, package absent, target released, and `!observationFailed`.
2. **Ownership clearing after launched removal:** In `confirmSelectedUninstall` (`InventoryViewModel.swift:533-539`), if `result.snapshot` is nil and `result.outcome.processStarted` is true, `clearOwnership(for: registryID)` executes, removing verified ownership from the snapshot and disarming the Uninstall button in `ToolDetailView`.
3. **Single mutation slot & sheet exclusion:** `prepareSelectedUninstall`, `confirmSelectedUninstall`, `prepareSelectedUpdate`, and `confirmSelectedUpdate` all guard against concurrent pipelines, and `invalidatePendingUpdate` safely tears down unconsumed preparations without interrupting launched mutations.

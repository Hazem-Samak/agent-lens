## Reviewed AGENT_LENS_SCOPE.md — product & architecture opinion

Project: **Agent Lens** — open-source native macOS utility that discovers/manages AI dev tooling (agents, coding tools, harnesses, package managers) installed on a Mac.

Only one doc in repo: `AGENT_LENS_SCOPE.md` (19 sections, fairly mature).

### Agreed direction (user-stated convention)
- **macOS native stack confirmed by user**: Swift 6 + SwiftUI (AppKit where needed), Foundation, `Process`, SPM, macOS-first.
- No Electron / Tauri / React / WebView / Rust-GPUI for the initial implementation.
- Discovery engine must stay a **separate SPM module with zero SwiftUI dependency** so Phase 1 CLI (`agent-lens scan`) and unit tests are possible.

### Key critique points raised
1. Real differentiator = **PATH-resolution / duplicate-install diagnostics**, not "update". Updates are already handled by `brew upgrade` / `npm update -g` in bulk.
2. **Underestimated risk — macOS PATH inheritance**: GUI `.app` bundles do NOT inherit the login shell PATH (`.zshrc`/`.zprofile`). App must resolve login-shell env explicitly or npm/brew binaries won't be found.
3. **Underestimated risk — version/update detection fragility**: "latest version" needs network calls with per-package-manager semantics (npm `latest` vs `wanted`, brew API, PyPI). Standalone installs have no registry → need an explicit "unknown" state. Design must be network-optional + cached.
4. **Uninstall completeness**: removing just the standalone binary orphans node_modules/config/cache. V1 conservatism is correct.
5. **Distribution constraint**: cannot ship on Mac App Store (sandbox forbids spawning arbitrary processes). Plan for notarized direct distribution / Homebrew cask.
6. **Retention risk**: low-frequency-use tool. Mitigate with menu-bar presence + "N updates available" surfacing.

### Applied to doc (third pass)
Added **§29 Multi-Agent Team Configuration** (~940 → ~1100 lines). Key protocols:
- **Council independence is not automatic** — reviewers get artifact-only packets (diff + acceptance criterion + raw output), never the implementer's justification; adversarial falsifiable questions; different model family preferred.
- **Self-grading is the #1 risk** — implementer must not grade its own work; orchestrator re-runs acceptance in a clean shell and must personally observe a pass.
- **Branch divergence** — one branch per milestone (not per agent); reviewers read-only; orchestrator merges.
- **Model fit** — M2 (env resolution) is diagnostic not typing work: orchestrator implements it or escalate to strongest reasoning model. Rule: ambiguity → strongest model, volume → fastest.
- **Nightly instability** — pin build per milestone, back up data dir before upgrade (one-way migration), record build string in DECISIONS.md.
- **Context allocation** — orchestrator gets full doc; implementer gets only the task brief; reviewers get only diff + criterion.
- Task brief template with explicit `DO NOT TOUCH` line.
- Added **R12** to risk register (council independence / self-grading / branch divergence, High).

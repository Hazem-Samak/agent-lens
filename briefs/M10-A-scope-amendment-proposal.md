## Required behavior

1. Logical and physical aliases of the same observed directory can be safely opened under normal TMPDIR, retaining the observed device/inode check and `O_DIRECTORY | O_NOFOLLOW | O_CLOEXEC` protection at every walked physical component. Do not weaken the walk into an ordinary following `open`, remove ancestor checks or normalize physical components back through Foundation before opening.
2. `DirectoryIdentity` records an internal, non-public `physicalPath: String` alongside the existing `canonicalPath` and identity facts; focused tests access the internal type through `@testable`, with no public accessor or widened visibility. Capture it with POSIX `realpath(3)` during directory observation, verifying the resolved physical path matches the same observed device/inode. Resolution/identity failure produces no directory observation. The opener keeps its current `openVerifiedDirectory(path:expected:)` signature: the existing protected caller passes its observation's `canonicalPath`, so require exact `path == expected.canonicalPath` as a consistency check. AC10 observes each logical/physical alias separately and calls the opener with that observation's canonical path; it does not require accepting an arbitrary noncanonical argument with another observation. Descriptor walking uses only the recorded `expected.physicalPath`. Split that recorded absolute string directly into components without URL standardization; reject empty/degenerate components or `.`/`..` instead of repairing them. Do not re-resolve a changed lexical path at open time and bless a new target. No protected caller needs edits; a new caller-file requirement stops implementation for a revised proposal.
3. The two spellings have different consumers: existing containment/manager-root comparison, public selected-entry/canonical-target/manager-root presentation and existing cache-key logic continue to consume the existing canonical fields on both sides. Only descriptor-relative directory opening consumes the captured physical field. Never compare physical components on one side with canonical/display components on the other. Do not expose, serialize, cache-key or production-log the new field. Equality intentionally retains all existing canonical/device/inode/mode checks and includes the recorded physical binding to reject a changed binding; controlled aliases that yield identical original identity facts must yield the same physical binding and remain equal. Test that condition explicitly. Physical-path equality is not a replacement for device/inode checks. Executable/file canonical strings and all other cache identity semantics are unchanged.
4. Missing paths, symlink loops, access errors or inability to obtain the physical directory identity fail closed. Preserve neutral reason policy and avoid following a manifest symlink or reading a FIFO/device. No test-only production switch or special treatment of `/tmp`/`/var`; resolve the filesystem facts rather than hardcoding a `/private` prefix.
5. Replacement/retarget between observation and open must not transfer the original proof. Test an ancestor replacement and directory replacement with distinct device/inode as applicable, plus the existing M9 npm manifest/prefix/bin race and malicious-layout regressions. No mutable global process environment or production retry.
6. Fixture corrections must preserve intended behavior under scratch both inside and outside HOME and logical/physical spellings, without creating files under personal configuration/install roots. In the PathDiagnostics fixture, replace only the invalid `"~" + extraRoot.path.dropFirst(home.count)` derivation with a correct relative derivation from the actual home to the owned extra root; keep tilde coverage, all extra-root ordering, selected-candidate, version and rendering assertions. In the coordinator fixture, replace only the raw `cwd=workingDirectory.path` spelling expectation with physical directory identity/spelling verification; keep exact `counts=3,0`, `inputs=true`, `identity=true`, `cacheHit=true`, subprocess exit and empty-stderr checks. Both failures have measured pristine-baseline receipts and must demonstrate passing-after under inherited TMPDIR. No skipped/vacuous assertion, policy weakening or unrelated test migration.
